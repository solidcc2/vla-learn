# 开发与训练流程备忘

目标：先跑通“本地开发 → 云端训练 → 模型回传”的最小闭环，再优化模型。

## 1. 初版代码

- 加载 CIFAR-10，完成训练、验证和模型保存。
- 支持 epochs、batch size、数据目录和输出目录等命令行参数。
- 保存 checkpoint，并能重新加载进行推理。

## 2. 本地 CPU 验证

- 使用少量数据或 1 个 epoch 做冒烟测试，不追求准确率。
- 确认数据加载、前后向传播、指标输出和模型保存均正常。

## 3. 阿里云准备

- 开通 PAI 工作空间、PAI-DLC 和 OSS。
- 配置 RAM 权限，并授权 DLC 访问 OSS。
- PAI、DLC 和 OSS 尽量选择同一地域。

## 4. 本地工具

- 安装并配置 `aliyun`、`pai` 和 `ossutil`。
- 如需自定义训练环境，再安装 Docker 并使用 ACR。
- 密钥不得写入代码、配置样例、镜像或 Git 仓库。

## 5. 数据与产物

- CIFAR 数据首次下载后保存到 OSS，后续任务重复使用。
- 任务启动时将数据复制到 DLC 临时盘，再从本地盘训练。
- checkpoint、最佳模型和必要日志写回 OSS。

## 6. 云端冒烟测试

- 先提交 1 个 epoch 的低成本 CPU 或最小 GPU 任务。
- 验证镜像、代码、OSS 读取、日志、训练和模型回传。
- GPU 任务需确认 PyTorch 可以识别 CUDA。

## 7. 正式训练

- 冒烟测试通过后增加 epochs，并选择合适的 GPU。
- 加入学习率调度、最佳模型保存、断点续训和费用限制。

完成标准：本地运行成功，云端任务正常结束，日志可见，模型成功保存到 OSS 并可下载验证。
