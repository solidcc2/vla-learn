# 训练制品与存储

制品核验需要确认内容、发布位置、版本、目标环境可读性及保存完整性。制品结构、打包白名单与完成协议以子项目代码为准。

## 挂载检查入口

1. 先定位目标子项目的挂载脚本、说明和配置。本仓库子项目通常由 `scripts/oss-mount.sh` 调用共用脚本；读取脚本确认接口和环境变量，再调用它的 `status`。
2. 读取状态输出中的每个所需挂载点、Bucket/前缀、文件系统和读写权限。**当前脚本即使输出 not mounted 也可能退出 0**，不能只根据退出码判断全部就绪。
3. 参数缺失时先从实际项目配置确认。可以用精确挂载点查询补充现状，但不据此猜 RAM 角色、改挂载目标或掩盖脚本状态检查未完成。
4. 所需路径未挂载时，使用同一脚本挂载再复查。路径存在、父目录属于某文件系统都不能证明它是预期 OSS 挂载；发现错误来源、非空普通目录或只读目标时，不向其写入。

已存在的有效挂载可直接发布；只有挂载不可用或用户指定其他入口时，再核对官方上传工具。内网和实例元数据的代理处理遵循现有挂载脚本，不重新实现。

## 制品发布

- 使用项目已有打包入口，检查源码制品与本次意图是否一致，避免把当前源码和旧制品混称一个版本。数据不变时复用其已核验版本。
- 使用新的版本目录，不覆盖正在或曾经运行的制品。目标已存在时先检查发布状态；不能通过覆盖把它悄悄变成新内容。
- 按项目协议先写内容，再写消费者用来判断完整性的清单或完成标记。例如项目要求 SHA256SUMS 最后发布时遵守此顺序；不要另造一个消费者不会读取的成功标记。
- 发布中断后检查已有对象和摘要，再决定续传或使用新版本；内容完整前不标记发布成功。
- 制品证据包含 URI、版本标识、manifest/摘要、核验方法、可用状态及尚未确认的事项。

## 持久化与结果验收

| 检查 | 证据范围 |
|---|---|
| 挂目录复制或读回载 | 当前客户端可见，可能命中缓存 |
| OSS API 列出对象 | 远端对象存在，不证明其内容摘要正确 |
| 下载或读取后重算摘要 | 对应内容符合清单，说明读取路径及是否独立下载 |
| 实际 DLC 读入并保存 | 本次任务访问与归档通过，不证明全部故障场景 |

通过项目已有发布和校验入口确认制品完整性，并如实说明核验范围。远端对象存在不等于内容已校验。

本地 ECS 的挂载身份、权限和参数不代表 DLC 的服务角色与挂载配置。分别检查输入读取、结果写入；只读结果挂载可用于查看；写入归档需要对应目标具备写权限。用于恢复的 checkpoint 需有完整性证据。
