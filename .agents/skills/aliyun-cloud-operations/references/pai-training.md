# PAI 训练入口

## 找到适用的官方能力

先检查 `pai --help`、`pai dlc job --help` 和目标子命令帮助。任务目录若已有有效配置，直接沿用。缺少操作时再检查 `aliyun pai-dlc` / `aiworkspace` 的对应 API。

- [PAI DLC 命令文档](https://help.aliyun.com/zh/pai/developer-reference/dlc-distributed-training)：配置文件、预览、提交、状态、日志与恢复操作的当前用法。
- [OpenAPI 开发者门户](https://api.aliyun.com/)：检索 PAI DLC 的任务创建、查询及资源接口，按适用版本读取字段与限制。
- [PAI 官方文档](https://help.aliyun.com/zh/pai/)：环境准备、服务授权、存储、镜像和计费说明。

本页保留工作流程；具体参数、默认值、字段类型和配置样例从当前帮助与上述官方文档获取。

## 配置文件选择

优先使用官方直接消费的 YAML/JSON。专用 CLI 的简化配置和底层 API 请求体可能采用不同字段体系，先确认文件属于哪一种，再选择对应读取入口；不要把两者混用。

将已有请求转换成 YAML 时，利用官方预览比较转换前后的字段、类型和启动命令。需要多行命令时选择符合执行语义的 YAML 字符串格式。能由官方工具读取的配置，不另写转换或提交包装脚本。

## 准备与执行

1. 确认工作空间、地域、镜像、计算规格及计费条件；选型使用 [实例与价格](compute-pricing.md)。
2. 核对输入路径存在、版本对应，运行结果路径具有写权限。ECS 挂载成功不代表 PAI 服务角色有同样权限。
3. 明确平台职责：DLC 按请求配置准备容器挂载，再执行启动命令；训练入口使用已挂载的路径。具体代码 staging 与结果保存协议由项目定义。
4. 使用本机支持的官方预览入口，检查即将提交的实际文件及最终请求。
5. 用户已授权创建任务时，以同一配置提交并记录返回的任务 ID。若仅要求改配置或预览，交付文件和验证结果即可。
6. 通过专用 CLI 检查任务状态和日志。恢复、重跑沿用项目的 checkpoint 协议；云端任务 ID 与训练代码生成的 run ID 分别记录。

挂载后能够读回文件不必然证明 OSS 上传完成，可能命中缓存；要求持久化确认的项目应验证实际挂载版本及写入/关闭语义。创建任务成功也不代表训练或归档成功。

超时后重试提交之前查询原任务是否已创建；停止和清理按用户指定范围执行。
